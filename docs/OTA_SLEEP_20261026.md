# OTA y retroiluminación — corrección del 26/10/2026

Placa confirmada por el usuario: **Elecrow CrowPanel V3**, no Waveshare. Se mantienen pines RGB, táctil, PSRAM, particiones, drivers físicos y UI de check-in.

## Causa reproducida en el receptor 2.4.13

COM5 registró descarga HTTP 200 completa, Content-Length y SHA coincidentes y esp_ota_write=ESP_OK, seguida de:

```
bootloader_mmap: tried to bootloader_mmap twice
esp_image: bootloader_mmap(0x1d0020, 0x61650) failed
cico.ota.update_end: esp_err=5379 ESP_ERR_OTA_VALIDATE_FAILED
```

`updateStatus()` ejecutaba `ESP.getSketchSize()` cada segundo. En Arduino-ESP32 2.0.17 esa función llama a `esp_image_verify`. Éste comparte el mapeo no reentrante de bootloader con `esp_ota_end()`. Ambas tareas competían por él. No era un binario truncado ni un SHA erróneo. El 0% provenía del receptor antiguo: no notificaba progreso durante la descarga y reportaba este error con cero.

Se calcula y guarda el tamaño una vez en setup, **antes** de iniciar CicoOtaClient. No se elimina ninguna validación de la nueva imagen. El receptor conserva hash, límites, verificación ESP, arranque confirmado y rollback. Añade lectura/hash de flash, progreso de fase y diagnóstico del código ESP y mensajes de validación. `scripts/check_ota_scanner.py` y CI impiden reintroducir la exploración periódica.

## Pantalla

La configuración anterior sólo atenuaba a 72/255. La política nueva pone el PWM de GPIO2 a cero tras 60.000 ms sin contacto; mantiene CPU, RGB, Wi-Fi, OTA y controladores en ejecución. Sólo un contacto válido puede despertar. Se consume el gesto completo, incluidas muestras sin datos frescos, hasta una liberación válida. Las acciones de UI y temporizadores de red no pueden despertar.

Al despertar se invalida/redibuja LVGL y se espera la transferencia antes de encender el backlight. Si no hay tema remoto, el respaldo Steinbock conserva textos/colores/QR y no concede autorización de llaves. Además se corrige el contraste del aviso sin tema, que antes dibujaba texto y fondo #eeeeee. No se cambia ni se sobreescribe ningún tema persistido.

## CICO

Valida todos los segmentos, longitudes, alineación, checksum y hash interno antes de aceptar una imagen; verifica SHA también al distribuir el archivo, detectando alteraciones del mismo tamaño. Conserva el diagnóstico OTA autenticado como evento del dispositivo. La UI explica el error de validación y la limitación del 0% en receptores antiguos. No declara SUCCESS sin versión/build y salud confirmados.
